# Deploy FileGo to Render

This deployment runs the Flask API and the built React frontend on **one Render web service**.

## Before deploying

- This Blueprint specifies a **paid Starter web service with a persistent disk**. Review Render's current pricing before approving creation.
- The SQLite database and uploaded files are stored on the disk at `/var/data`. Back them up separately. Do not use an ephemeral free web service for permanent user data.
- Do not seed or use demo accounts with known passwords on a public deployment. Use dummy files for initial tests.
- Public deployment changes the network conditions of FileGo. Keep the LAN version for LAN throughput experiments.

## Create the service

1. Merge the deployment pull request into `main`.
2. Open [Render Dashboard](https://dashboard.render.com/), choose **New > Blueprint**, and connect `Kenzaide/FileGo`.
3. Review `render.yaml` and **the paid service and disk costs**. Confirm only if acceptable.
4. Deploy and wait for the service to become healthy.
5. Open `https://<your-service>.onrender.com/api/ping` and confirm a successful response.
6. Open the service root URL, register a new test account, and test upload/download with a dummy file on desktop and mobile.

The app uses the Render-provided `PORT` environment variable. The `SECRET_KEY` is generated by Render and should never be committed to GitHub.

## Operational notes

- A single SQLite database on a persistent disk is appropriate only for a small, single-instance demo. Do not scale this service to multiple instances without moving to a suitable shared database and file storage.
- Review user registration policy, HTTPS cookie settings, backups, upload limits, and account administration before sharing the link broadly.
- Keep the existing local `start-demo.bat` workflow for offline demonstrations.
